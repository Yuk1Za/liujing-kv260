# 数据接口

## 传感器与视觉

相机采集位于 `runtime.cpp` 的 `acquire()`。RGB-D 配对后，原帧进入融合队列，RGB JPEG 发布为 `sensor_msgs/CompressedImage`，话题 `/liujing/camera/color/compressed`。消息时间戳使用映射到 ROS 时钟的采集时刻。

`visual_node.py` 订阅该图像和 C16 `/point_cloud_raw`，按时间戳关联点云。`PLMatcher.match(gray_prev, gray_cur, det="st")` 返回 `uv_prev` 与 `uv_cur`；前帧点云按相机内外参投影得到 `lidar_uv` 与 `lidar_z`，传入 `PnPVO.step`。输出为累计视觉位姿，经相机到机体外参变换后发布至 `/vo_pnp/abs`（`geometry_msgs/PoseStamped`）。

`visual_frontend.py` 同时提供注册 RGB-D 输入接口 `RGBDFrame`，适用于直接从深度图对特征赋深。

## 后端与融合

`map_optimization.cpp` 订阅 `/vo_pnp/abs`，按关键帧时刻关联视觉位姿并添加 BetweenFactor。连续雷达里程计 `/odom_init/laser_odom` 与后端优化结果 `/mapping/odometry` 使用 `nav_msgs/Odometry`。

融合程序订阅上述两路位姿，以优化结果为锚点并结合连续运动，计算 RGB-D 帧对应的位姿。深度反投影后进行面元关联，更新位置、法向、RGB、权重与地图版本。地图容量为 2,000,000 点。

## 硬件访问

统一入口加载 `hardware/final3/kv260_final3.bit`。雷达与视觉进程复用该位流，通过 AXI-Lite 控制和 DDR 缓冲区传递数据。具体地址、寄存器和缓冲区格式见 HWH、各 IP 驱动与主机控制源码。IP 包含雷达特征、Shi-Tomasi、NMS、sparse LK 和 s2m；主流程由统一启动文件选择模块。

## 地图传输

8090 提供 `/status` 和 `/camera.jpg`，8092 提供 `/color?after=<version>`。LJCD 数据包由四字节标记、四字节小端 JSON 长度、JSON 元数据与点记录组成。每条点记录 20 字节：`uint32 id + float32 x/y/z + uint32 rgb`。

元数据含 session、version、base_version、full、map_count 和 source_stamp。电脑端首次读取全量，随后按稳定 ID 应用增量；新会话或版本不连续时请求全量。网页服务端口为 8097。
